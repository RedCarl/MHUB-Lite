# 界面与交互：Solid Glass for a Device Tool

> 材质来自 TinyMusic 的 `src/app.css`，后者移植自
> [solid-glass](https://github.com/deeplethe/solid-glass)（MIT）。
> MHUB Lite 没有引入 Tailwind / shadcn / React，所有规则都是一份普通 CSS。
>
> 这套文档描述「为什么这样排」，不是一份 API 手册。

---

## 1. 四条材质规则

1. **收边在边缘。** 顶上一道高光、四周一圈发丝线、底下一层阴影；面板正面保持中性，
   不铺渐变，不靠「亮一点 / 暗一点」的色块制造层次。
2. **厚重，不发飘。** 颜色中性；玻璃只柔化背后的东西，不给它上色。
3. **深度即厚度。** 薄 → 中 → 厚：`--panel` / `--bg2` / `--popover`。
   越浮在上面的东西越厚、越不透。
4. **只有一种选中态。** 悬停、选中、展开用同一小块透明玻璃：
   一层很淡的着色、顶上一道高光、四周一圈发丝线，没有阴影。
   需要更明确时用 `--glass-state-armed`，而不是另起一套颜色。

颜色只留给有意义的东西：在线（绿）、充电（绿）、低电量（红）、警告（琥珀）、
正在写入（品牌青）。其余全是墨与灰。

## 2. 外壳

```
┌────────────────────────────────────────────────────────────┐
│ 标题栏（Windows 自绘；macOS 用系统红绿灯 + Overlay）        │
├───────────────┬────────────────────────────────────────────┤
│ 侧边栏 212px  │ 内容区：内缩 8px 的圆角玻璃                │
│ 不铺底        │ 四周发丝线 + 脚下一层浅影                   │
│ 分组只靠间距  │                                            │
│               │                                            │
│ …             │ 页面：26px 32px 44px，最大 1280px          │
│               │                                            │
│ 设备脚注      │                                            │
├───────────────┴────────────────────────────────────────────┤
│ 底部设备栏：全站唯一的液态玻璃，胶囊形，浮在内容上          │
└────────────────────────────────────────────────────────────┘
```

### 侧边栏

- 宽度 `212px`，不铺底、不描边、不画分割线；分组用一个 `.nav-sep` 的间距。
- 选中态不是加在按钮上的背景，而是一块独立的 `.nav-ind` 玻璃：
  它测量当前 `button.on` 的位置，用 280ms 的缓动滑过去。
- 顶部给 macOS 红绿灯留 `46px`（`--titlebar-inset`），这块区域可拖动窗口。
- Windows 下品牌搬到自绘标题栏，侧栏不再重复品牌。

### 内容区

- `main` 四周内缩 8px，`--panel` 薄底 + 一圈发丝线 + 脚下一层阴影。
  页面与它的色差很小，层次靠边缘而不是第二种底色。
- 页面 `max-width: 1280px`，居中；窗口拉宽时内容跟着长，不会全堆在右边。
- 路由切换时把内容区滚回顶部。

### 底部设备栏

播放器栏是原设计里唯一的液态玻璃，这里换成设备栏，承担同样角色：

- 左侧：设备图标、名称、连接方式、电量，点击回概览；
- 中间：同步状态（已同步 / N 项未写入 / 休眠中），一行标题 + 一行说明；
- 右侧：重新读取、还原、写入设备（墨色实心胶囊）；
- 液态玻璃：24%（浅色 55%）底色 + `blur(56px) saturate(220%) brightness(1.10)`，
  左上镜面反光与顶边高光，顶边高光比其他玻璃更亮。

它同时也是「写入工作流」的固定落点：无论在哪一页，用户都能看到有没有未写入的改动，
以及写入按钮是否可用。

## 3. 页面结构

五个一级页面，没有详情页：

| 页面 | 内容 | 交互重点 |
|---|---|---|
| 概览 | 设备主卡、电量、固件、硬件 ID、四张统计卡、DPI 阶梯、按键摘要 | 点击统计卡进入对应页；鼠标预览可点 |
| DPI | 档位数量、当前档位、每档 DPI 滑块 + 数字输入 + ±100 | 点档位圆钮切换当前档；改动即时进入草稿 |
| 按键 | 5 行按键映射、滚轮方向、SVG 预览 | 悬停行时预览高亮；左键锁定；下拉选择 |
| 性能 | 回报率、防抖、休眠、LOD | 分段控件 + 滑块 + 快捷值芯片 |
| 设置 | 外观、设备偏好、当前设备、关于 | 改动即保存偏好；诊断复制 |

### 页面头

```text
标题（26px，700）              [次要按钮] [主按钮]
说明（13px，fg2，最多 64ch）
```

按钮统一 34px 高；页面头在窄窗口会换行，标题优先。

### 卡片

- 中厚度：`--bg2`（深色 46% 白）+ `--pane-shadow`；
- 卡片头：标题 14px / 650，说明 11.5px / fg3；
- 卡片内边距 18–20px，卡片之间 10px；
- 不嵌套卡片；需要分组时用一条 `--line-soft` 分隔。

## 4. 控件

| 控件 | 材质 | 规则 |
|---|---|---|
| `.btn` | 一小块透明玻璃 | 次要动作；悬停变亮；禁用 40% 不透明 |
| `.btn.primary` / `.bar-apply` | 墨色实心玻璃 | 一屏只放一个主要动作 |
| `.seg` | 一个托盘 + 选中的一块玻璃 | 段数与选中项都用它；不再创造第二种分段样式 |
| `.switch` | 凹槽 + 墨色实心轨道 | 开关状态靠位置和颜色同时表达 |
| `input[type=range]` | 凹槽 + 墨色填充 + 最亮圆点 | DPI / 防抖 / 休眠 |
| `<select>` | 输入框材质 | 按键动作；系统菜单用原生渲染 |
| `.badge` | 小玻璃 | 连接方式、在线、演示；在线/警告才上色 |

所有可交互元素都有 `:focus-visible` 的 2px 线，不套光圈。

## 5. 草稿 / 写入

这是设备工具与播放器最重要的差异：

1. 连接时从设备读一份快照，保存在 `device.current`；
2. 所有编辑落在 `draft` 上，不立刻碰硬件；
3. 底栏比较 `draft` 与快照，按组显示「DPI / 回报率 / 防抖 / 休眠 / LOD / 滚轮方向 / 按键」未写入；
4. 「还原」丢弃草稿；「写入设备」把草稿写进板载 Flash；
5. 写入成功后再读一遍设备快照，草稿回到干净状态。

只有同时满足「在线 + 有草稿 + 有改动 + 不忙」时，写入按钮才可用。
休眠时按钮禁用，并把原因写在底栏说明里。

**为什么不做改动即写入？** 参考项目 M-RustHub 采用即时保存，适合频繁微调；
但一次误触就会写 Flash，且鼠标固件在写按键时会短暂重枚举。MHUB Lite 选择
「先确认再写」：明确的动作、明确的落点、可撤销。

## 6. 鼠标预览

- 一个俯视的 SVG，只用 `currentColor` 的派生变量，不依赖位图；
- 左/右/中/前进/后退各是一个可聚焦的 `<g role="button">`：
  - 悬停/聚焦：品牌青 22% 填充 + 55% 描边；
  - 当前行被悬停时从外部传入 `highlight`，预览同步亮起；
  - 点击把用户带回按键页对应的行；
- 机身上的滚轮、DPI 点、底部灯带、右侧键槽都是实际硬件特征的简化，
  不是装饰插画。

概览页的预览点击直接进入按键页；按键页的预览用于确认「我改的是哪一颗」。

---

## 7. 深色与浅色

- 深色是设计本身的形态（`:root`），浅色是同一套玻璃在天光下（`:root[data-theme='light']`）。
- 两套令牌名字相同，组件里没有一处 `data-theme` 分支；
  浅色块里只剩「不能靠颜色表达」的几处修正（自动填充、遮罩、鼠标预览的边线）。
- 主题有「跟随系统 / 浅色 / 深色」三档，存在 localStorage，启动时在挂载前应用，避免首帧闪色。

---

## 8. 无障碍与退路

- `prefers-reduced-motion: reduce`：关闭所有动画与过渡；
- `prefers-reduced-transparency: reduce`：去掉模糊、玻璃换实色，高光/阴影保留；
- 键盘可达：侧栏、分段、开关、滑块、select、鼠标预览热区都可 Tab；
- 图标按钮都有 `aria-label` / `title`；
- 电量用 `role="meter"` 并带 `aria-valuenow`；
- 所有颜色之外的状态都同时有文字（在线 / 休眠 / 充电 / 演示）。

---

## 9. 响应式

- 侧栏固定；内容区在 1280px 处停止变宽；
- ≤1180px：设备主卡左列收窄，统计卡从 4 列变 2 列；
- ≤1080px：按键页右列收窄；
- ≤1020px：性能页三列改单列；
- ≤980px：两列卡片改单列，按键页预览挪到下方；
- ≤900px：设备主卡改单列，空状态图在上、文案在下。

窗口最小 900 × 600；默认 1140 × 760。

## 10. 和 TinyMusic 的差异

| TinyMusic | MHUB Lite |
|---|---|
| 播放器栏 + 队列 + 歌词页 | 设备栏 + 5 个设置页 |
| 曲目行 | 参数行 / 按键行 |
| 下载弹窗、右键菜单 | 无（动作都在页面内） |
| 托盘、账号、网盘 | 无（完全离线） |
| 液态玻璃播放器 | 液态玻璃设备栏（同一个令牌体系） |

保持不变的是：窗口外壳、侧栏滑动指示、页面节奏、卡片厚度、
分段控件、开关、滑块、toast、主题切换和「一种选中态」的约束。
