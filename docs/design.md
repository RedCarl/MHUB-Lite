# 界面与交互：Solid Glass for a Device Tool

> 材质来自 TinyMusic 的 `src/app.css`，后者移植自
> [solid-glass](https://github.com/deeplethe/solid-glass)（MIT）。
> MHUB Lite 没有引入 Tailwind / shadcn / React，所有规则都是一份普通 CSS。

---

## 1. 四条材质规则

1. **收边在边缘。** 顶上一道高光、四周一圈发丝线、底下一层阴影；面板正面保持中性，
   不铺渐变，不靠「亮一点 / 暗一点」的色块制造层次。
2. **厚重，不发飘。** 颜色中性；玻璃只柔化背后的东西，不给它上色。
3. **深度即厚度。** 薄 → 中 → 厚：`--panel` / `--bg2` / `--popover`。
   越浮在上面的东西越厚、越不透。
4. **只有一种选中态。** 悬停、选中、展开用同一小块透明玻璃：
   一层很淡的着色、顶上一道高光、四周一圈发丝线，没有阴影。
   需要更明确时用 `--glass-state-armed`，而不是另起一套颜色。

颜色只留给有意义的东西：在线（绿）、充电（绿）、低电量（红）、警告（琥珀）、
正在写入（品牌青）。其余全是墨与灰。

## 2. 外壳

```
┌────────────────────────────────────────────────────────────┐
│ 标题栏（Windows 自绘；macOS 用系统红绿灯 + Overlay）        │
├───────────────┬────────────────────────────────────────────┤
│ 侧边栏 212px  │ 内容区：内缩 8px 的圆角玻璃                │
│ 品牌           │ 四周发丝线 + 脚下一层浅影                   │
│ 设备切换       │                                            │
│ 导航           │ 页面：26px 32px 40px，最大 1280px          │
│ …             │                                            │
│ 设备脚注+状态  │                                            │
└───────────────┴────────────────────────────────────────────┘
```

### 侧边栏

- 宽度 `212px`，不铺底、不描边、不画分割线；分组用一个 `.nav-sep` 的间距。
- 选中态不是加在按钮上的背景，而是一块独立的 `.nav-ind` 玻璃：
  它测量当前 `button.on` 的位置，用 280ms 的缓动滑过去。
- 顶部给 macOS 红绿灯留 `46px`（`--titlebar-inset`），这块区域可拖动窗口。
- Windows 下品牌搬到自绘标题栏，侧栏不再重复品牌。
- 品牌标记使用用户提供的 MCHOSE 单色 SVG，颜色跟随 `currentColor`，
  放在墨色方块里，深色下白、浅色下黑。

### 设置按钮

「设置」不参与页面导航，固定在侧栏最下方、设备脚注上方：

- 一枚独立的实心玻璃按钮：齿轮 + 居中「设置」，带描边与轻微投影；
- 当前在设置页时用品牌青着色，而不是滑动指示块；
- 导航测量只查询 `.side-nav button.on`，不会把这枚按钮当成导航项。

### 设备切换

鼠标与键盘同时连接时，品牌下方出现一块两段式玻璃：

```
[ 鼠标 ] [ 键盘 ]
```

- 只连接一台时不出现；连接两台时默认选鼠标。
- 切换会同步更新导航项（鼠标有 DPI，键盘有灯效；A7 没有按键页）。
- 切换后如果当前路由对新设备无效，自动回到概览。

### 保存状态

原设计里的底部播放器栏被**移除**了：它不是这个项目的语义，也不应该占据内容区底部。

保存状态改为设备脚注的一部分：

- 设备名下方：`USB 有线 · 77% · 已保存` / `2.4G 无线 · 95% · 保存中…`；
- 脚注头像右下角的小点：在线为绿、保存中为琥珀、离线为灰；
- 写入失败时，内容区顶部出现一条红色提示条，说明具体原因；
- 页面标题行在写入时也会出现「保存中… / 已保存」小胶囊。

页面底部不再有悬浮的胶囊栏；`main` 只保留 40px 的底部留白。

## 3. 页面结构

导航随当前设备变化：

| 设备 | 页面 |
|---|---|
| 鼠标 | 概览、DPI、按键（仅 G3 V2）、性能 |
| 键盘 | 概览、按键、灯效、性能 |
| 设置 | 侧栏底部独立按钮，不占导航 |

| 页面 | 内容 | 交互重点 |
|---|---|---|
| 概览（鼠标） | 设备主卡、电量、固件、硬件 ID、统计卡、DPI 阶梯、按键摘要 | 点统计卡进入对应页；鼠标预览可点 |
| 概览（键盘） | 99 键缩略图、电量、连接、当前灯效、统计卡 | 点统计卡进入改键 / 灯效 / 性能 |
| DPI | 档位数量、当前档位、每档滑块 + 数字输入 + ±步进 | 点档位圆钮切换当前档；改动即时写入 |
| 按键（鼠标） | 5 行按键映射、滚轮方向、SVG 预览 | 悬停行时预览高亮；左键锁定 |
| 按键（键盘） | Default / Fn / Fn2 三层、99 键矩阵、检查器 | 点任意键改映射；改动即时写入 |
| 灯效 | 灯效模式、亮度、速度、颜色、多彩 | 控件即时写入；按模式启用/禁用 |
| 性能 | 鼠标：回报率/防抖/休眠/LOD；键盘：回报率/延迟/休眠/系统键 | 分段、滑块、开关 |
| 设置 | 外观、设备、已连接设备、诊断、关于 | 切换 / 断开设备，复制诊断 |

### 页面头

```text
标题（26px，700）              [保存状态] [次要按钮] [主按钮]
说明（13px，fg2，最多 64ch）
```

### 卡片

- 中厚度：`--bg2`（深色 46% 白）+ `--pane-shadow`；
- 卡片头：标题 14px / 650，说明 11.5px / fg3；
- 卡片内边距 18–20px，卡片之间 10px；
- 不嵌套卡片；需要分组时用一条 `--line-soft` 分隔。

## 4. 键盘矩阵

- 99 个物理键，按官方布局的**相对偏移累加**规则重新实现：每行从 `backquote`、`Tab`、
  `Caps`、`Left_Shift`、`Left_Ctrl` 开始，单位 38px、键缝 4px。
- 容器用 `aspect-ratio` 维持 786 : 228 的比例，按键用百分比绝对定位。
- 键帽分为两层信息：主标签（Esc / F1 / Q）和可选的映射标签（只有改过或修饰键才显示）。
- 选中键：品牌青 22% 填充 + 55% 描边；点击后在下方检查器里修改。
- 检查器提供：
  - 常用动作下拉（默认、字母、数字、F 键、导航、修饰键、媒体键、Fn）；
  - 自定义 4 字节十六进制输入；
  - 「恢复此键默认」：Default 层回到官方默认码，Fn / Fn2 回到官方 Fn / Fn2 默认码。
- 三层标签是唯一的段选控件；切换层只换数据，不改设备。

## 5. 即时保存

设备工具不需要「草稿 → 应用」两段式：

1. 修改直接落在当前设备快照上，界面立即响应；
2. 300–450ms 的合并窗口结束后写入；
3. 鼠标写整块配置 / DPI；键盘写性能块、灯效块或某一句层键表；
4. 写入串行排队，回读确认；期间继续修改的值会在上一笔完成后接上；
5. 侧栏脚注与页面标题显示「保存中… / 已保存」，失败时显示错误条。

**为什么不做每改必写？** 键盘固件要求写入之间至少约 1.2 秒；滑块每一像素都写会
拖慢界面、反复擦写 Flash。合并窗口只合并短时间内的连续修改，不改变「最终写入」的语义。

**为什么没有「还原」？** 设备快照就是当前真值；要还原单个字段，直接把控件改回去即可，
它同样会即时写入。键盘的「恢复本层默认」是显式的数据重置，不是草稿操作。

## 6. 设备图

- 概览页优先使用 MCHOSE 官方网页驱动的产品渲染图（A7 V3 Ultra+ / K99 V2 / G3 V2，
  来自 `cdn.mchose.com.cn/configCenter`），仅用于识别已连接的型号；
  没有匹配型号时回退到内置 SVG。
- 产品图保持原始配色，不做主题反色；深色主题下用一圈很淡的径向背景托住白色机身，
  黑色键盘则靠 `drop-shadow` 和灰色舞台保持轮廓。
- 鼠标按键页仍使用内置 SVG，因为它需要五个可聚焦的按键热区；概览页不承担改键交互。

### 内置 SVG 鼠标

- 一个俯视的 SVG，只用 `currentColor` 的派生变量，不依赖位图；
- 左/右/中/前进/后退各是一个可聚焦的 `<g role="button">`：
  - 悬停/聚焦：品牌青 22% 填充 + 55% 描边；
  - 当前行被悬停时从外部传入 `highlight`，预览同步亮起；
  - 点击把用户带回按键页对应的行；
- 机身上的滚轮、DPI 点、底部灯带、右侧键槽都是实际硬件特征的简化。

概览页的预览点击直接进入按键页；按键页的预览用于确认「我改的是哪一颗」。

## 7. 深色与浅色

- 深色是设计本身的形态（`:root`），浅色是同一套玻璃在天光下（`:root[data-theme='light']`）。
- 两套令牌名字相同，组件里没有一处 `data-theme` 分支；
  浅色块里只剩「不能靠颜色表达」的几处修正（自动填充、遮罩、鼠标预览的边线）。
- 主题有「跟随系统 / 浅色 / 深色」三档，存在 localStorage，启动时在挂载前应用，避免首帧闪色。

## 8. 无障碍与退路

- `prefers-reduced-motion: reduce`：关闭所有动画与过渡；
- `prefers-reduced-transparency: reduce`：去掉模糊、玻璃换实色，高光/阴影保留；
- 键盘可达：侧栏、设备切换、分段、开关、滑块、select、键盘矩阵与鼠标预览热区都可 Tab；
- 图标按钮都有 `aria-label` / `title`；
- 电量用 `role="meter"` 并带 `aria-valuenow`；
- 所有颜色之外的状态都同时有文字（在线 / 休眠 / 充电 / 保存中 / 保存失败）。

## 9. 响应式

- 侧栏固定；内容区在 1280px 处停止变宽；
- ≤1180px：设备主卡左列收窄，统计卡从 4 列变 2 列；
- ≤1080px：按键页右列收窄；
- ≤1020px：性能页三列改单列，键盘主卡与灯效页改单列；
- ≤980px：两列卡片改单列，鼠标按键页预览挪到下方；
- ≤900px：设备主卡改单列，空状态图在上、文案在下。

窗口最小 900 × 600；默认 1140 × 760。

## 10. 和 TinyMusic 的差异

| TinyMusic | MHUB Lite |
|---|---|
| 播放器栏 + 队列 + 歌词页 | 无底栏；设备脚注 + 保存状态 |
| 曲目行 | 鼠标参数行 / 键盘矩阵 |
| 下载弹窗、右键菜单 | 无（动作都在页面内） |
| 托盘、账号、网盘 | 无（完全离线） |
| 液态玻璃播放器 | 仅保留标题栏、卡片与浮层的 Solid Glass；不再有液态玻璃底栏 |

保持不变的是：窗口外壳、侧栏滑动指示、页面节奏、卡片厚度、
分段控件、开关、滑块、toast、主题切换和「一种选中态」的约束。
